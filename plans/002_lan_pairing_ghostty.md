# PRD: LAN Pairing, QR Code, Ghostty Integration, and Menu UX

## Problem Statement

The Agent Session Control system's Mac and iPhone components cannot communicate over a real LAN today. The server binds only to loopback (127.0.0.1), performs no TLS handshake (the `https` scheme is cosmetic), and the iPhone is hardcoded to connect to `127.0.0.1:5577`. There is no QR code rendering on the Mac and no camera scanning on the iPhone; the pairing payload is an unwieldy JSON blob displayed as selectable text. The menu bar popover has a fixed 320 pt width that makes the pairing payload row dominate the layout. The Mac cannot open or focus the tmux session in Ghostty; users must copy and paste the attach command manually.

## Solution

Four changes delivered together because they share a dependency: real TLS on the server, which enables real LAN connectivity, which makes the QR invitation meaningful, which enables iPhone pairing.

1. **Real LAN Transport.** Replace the raw Darwin-socket loop with an `NWListener` (Network.framework) server bound to all interfaces, with TLS using a persisted self-signed certificate generated by the system `openssl` CLI. Advertise the service via Bonjour (`_agentctl._tcp`) so the iPhone can discover the Mac without a manual IP.

2. **QR Pairing.** Add `certFingerprintSHA256` and `bonjourServiceName` to `PairingInvitation`. Render the payload as a QR code image in the Mac menu bar (CoreImage). On iPhone, provide a camera scanner (DataScannerViewController) and a paste-text fallback. The iPhone pins on the cert SHA-256 fingerprint instead of trusting any certificate.

3. **Ghostty Integration.** After launching a Wrapped Session, automatically open or focus Ghostty on the tmux attach command. Reuse an existing Ghostty window via AppleScript keystroke (requires Accessibility permission); open a new window via `open -na Ghostty.app` if Ghostty is not running.

4. **Menu Bar UX.** Drop the fixed 320 pt width; let the popover size to its content. The QR image replaces the long payload text row, so remaining rows are short and the popover is compact by default.

## User Stories

1. As the owner, I want the iPhone to discover the Mac Agent on the local network without typing an IP address, so that setup is frictionless.
2. As the owner, I want to scan a QR code on the Mac menu bar with my iPhone to complete pairing, so that I don't need to copy-paste a JSON payload.
3. As the owner, I want a text-paste fallback for pairing so that I can pair even if camera access is unavailable.
4. As the owner, I want the pairing connection to be encrypted so that commands are not visible to other devices on the LAN.
5. As the owner, I want the iPhone to trust only the specific Mac Agent it paired with, so that a rogue server on the same LAN cannot intercept commands.
6. As the owner, I want the Mac Agent to auto-open Ghostty focused on the tmux session when a Wrapped Session starts, so that I don't need to find and paste the attach command.
7. As the owner, I want the Mac Agent to reuse an already-open Ghostty window rather than spawning another one, so that my workspace stays tidy.
8. As the owner, I want an "Open in Ghostty" button in the menu bar to re-focus the session on demand, so that I can return to it after switching to another app.
9. As the owner, I want the Mac Agent menu bar popover to size itself to its content, so that short rows are not stretched to fill unused space.
10. As the owner, I want Bonjour service discovery to resolve the Mac's current IP at connection time, so that the pairing survives DHCP lease changes.

## Implementation Decisions

- NWListener (Network.framework) replaces the raw Darwin BSD-socket server. `LocalControlAPIResponder` and `ParsedLocalControlAPIRequest` are unchanged; only the transport layer is swapped.
- Self-signed TLS certificate generated via `openssl req -x509 | openssl pkcs12` (matching the existing shell-to-CLI convention for git/gh/tmux). Certificate and PKCS12 stored in Application Support. Certificate SHA-256 fingerprint embedded in the `PairingInvitation` payload for pinning.
- Bonjour service type `_agentctl._tcp`, service name = `macAgentName`. iPhone stores `bonjourServiceName` in credentials and uses `NetService` to resolve current host:port before each session.
- iPhone cert pinning via custom `URLSessionDelegate` that validates the server leaf cert SHA-256 against the stored fingerprint; bypasses hostname validation (connecting to a resolved LAN IP, not the cert CN).
- `PairingInvitation` and `PairedControlCredentials` gain optional new fields (`certFingerprintSHA256`, `bonjourServiceName`) for backward compatibility with existing encoded payloads.
- Ghostty integration uses `osascript` for keystroke injection when Ghostty is running (needs Accessibility permission) and `open -na Ghostty.app` otherwise; wrapped in a non-fatal `GhosttyLaunching` protocol for testability.
- DataScannerViewController (VisionKit, iOS 16+) for camera scanning; requires a proper iOS app bundle with `NSCameraUsageDescription`. The paste-text fallback works with the existing SPM executable.
- Accessibility permission prompt is surfaced as a non-blocking menu bar error when AppleScript keystroke is attempted without it; session launch is never blocked.

## Testing Decisions

- Unit tests for `SelfSignedTLSIdentity` mock `ProcessCommandExecuting` to avoid shelling out; test that fingerprint is a 64-char hex string.
- Unit tests for `GhosttyLauncher` mock `ProcessCommandExecuting` and assert the correct `open -na` / `osascript` argument sequences.
- Unit tests for `PinningURLSessionDelegate` verify that a matching fingerprint accepts the challenge and a mismatching one cancels.
- Unit tests for `BonjourResolver` mock `NetService` responses.
- End-to-end: physical iPhone + Mac on the same Wi-Fi; `dns-sd -B _agentctl._tcp` confirms Bonjour advertisement; `openssl s_client -connect <lan-ip>:5577` confirms real TLS; full `docs/demo/full-lan-mvp.md` runbook executed over LAN (not loopback).

## Out of Scope

- Multiple paired devices (only one pair at a time in MVP).
- TLS client certificate authentication (bearer token + fingerprint pinning is the trust model).
- APNs push notifications (Milestone 2).
- Cloud relay (Milestone 3).
- Automatic DHCP re-pairing without user action (Milestone 2).
- Ghostty AppleScript suite for window management (not yet available in Ghostty).

## Further Notes

Camera scanning requires building `iPhoneApp` as a proper Xcode/xcodegen iOS app bundle to carry `NSCameraUsageDescription` in Info.plist. Until that bundle is set up, use the paste-text fallback. The code is structured so that adding the Xcode target is the only change needed to enable camera scanning — no Swift code changes required.

The Accessibility permission dialog for Ghostty AppleScript keystroke injection is shown by macOS the first time the keystroke is attempted. The owner must grant it once. If denied, the menu bar shows a warning and the "tmux Attach" command string remains available as the manual fallback.
